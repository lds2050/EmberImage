# EmberImage v0.5.0 需求文档

> 版本主题：图片编辑与参考图生成
> 文档状态：待评审
> 基线版本：v0.4.0
> 目标平台：Windows x64、macOS Apple Silicon、macOS Intel
> 更新时间：2026-08-27

## 1. 版本概述

v0.5.0 在现有文字生图与样例库能力上新增“图片编辑”工作流，使用户可以把一张或多张本地图片作为输入，通过自然语言完成整体重绘、风格转换、元素增删、多参考图合成，以及使用 Mask 指定区域的局部编辑。

本版本继续使用 OpenAI Image API，编辑请求发送到 `POST /images/edits`。它适合 EmberImage 当前“一次请求、得到一组结果”的桌面客户端形态。需要连续上下文、对同一张图多轮对话修改的 Responses API 工作流不纳入 v0.5.0。

## 2. 背景与依据

GPT Image 2 同时支持图片输入和图片输出，并提供 `v1/images/edits` 编辑端点。官方编辑接口支持一张或多张输入图片；传入 Mask 时，Mask 作用于第一张输入图片。GPT Image 的 Mask 是提示性约束，模型可能不会完全按像素边界执行。

与 v0.5.0 直接相关的官方规则：

- 编辑提示词必填，最长 32,000 个字符；
- GPT Image 模型的编辑请求最多可包含 16 张输入图片；
- Mask 只允许一张，并作用于第一张输入图片；
- 编辑图与 Mask 必须具有相同尺寸和格式，且均小于 50 MB；Mask 必须包含 Alpha 通道；
- `gpt-image-2` 自动以高保真方式处理全部输入图，不允许调整 `input_fidelity`，客户端应省略此参数；
- 输出仍支持 `size`、`quality`、`n`、`background`、`output_format`、`output_compression`、`moderation`、`stream` 和 `partial_images`；
- 流式请求最多可返回 3 张部分图预览；
- 透明背景仅适用于 PNG 或 WebP，不适用于 JPEG。

## 3. 产品目标

### 3.1 核心目标

1. 用户可以在“开始”页面明确选择“文字生图”或“图片编辑”。
2. 用户可以上传单张或多张参考图并调整顺序。
3. 用户可以对第一张输入图进行整体编辑或绘制 Mask 后局部编辑。
4. 用户无需理解 multipart、Alpha 通道等 API 技术细节，客户端自动完成格式校验和 Mask 转换。
5. 编辑结果可以像文字生图结果一样被预览、下载、复制、收藏、复用和记录。
6. OpenAI 兼容服务不支持编辑端点时，客户端能够给出可理解、可排查的提示。

### 3.2 成功标准

- 新用户无需阅读帮助文档即可完成一次单图整体编辑；
- 用户可在 3 分钟内理解并完成一次局部 Mask 编辑；
- 编辑请求的 API Key、图片二进制/Base64 和完整本地路径不出现在请求日志中；
- v0.4.x 的连接配置、样例库、文字生图记录和本地图片可以无损升级；
- 文字生图原有功能和交互不回退。

## 4. 非目标

以下能力不属于 v0.5.0：

- 基于 Responses API 的多轮对话改图；
- 图层、选区羽化、套索、魔棒、文字图层等专业图像编辑功能；
- Photoshop、Figma 等第三方软件插件；
- 云端素材库、账号同步和多人协作；
- 摄像头拍摄、扫描仪导入；
- 批量为不同输入图执行不同提示词；
- 自动抠图或通用图片格式转换工具；
- 对第三方兼容服务承诺与 OpenAI 官方完全一致的编辑能力。

## 5. 术语

| 术语 | 定义 |
| --- | --- |
| 文字生图 | 仅输入提示词和输出参数，通过 `/images/generations` 创建图片。 |
| 图片编辑 | 输入图片和提示词，通过 `/images/edits` 生成新图片，不直接覆盖原图。 |
| 主图 | 输入列表中的第一张图片；局部编辑时 Mask 只作用于该图。 |
| 参考图 | 主图之外的输入图片，用于提供人物、物体、风格、材质或构图参考。 |
| 整体编辑 | 不传 Mask，由提示词和全部输入图共同决定输出。 |
| 局部编辑 | 传入 Mask，要求模型重点修改主图中被标记的区域。 |
| 编辑区域 | 用户在 Mask 编辑器中涂抹的区域；客户端在发送前转换为 API 要求的 Alpha Mask。 |

## 7. 信息架构

左侧主菜单保持不变：

- 开始
- 画廊
- 设置

“开始”页顶部新增创作模式切换：

- 文字生图
- 图片编辑

进入“图片编辑”后，在素材区提供编辑范围切换：

- 整体编辑
- 局部编辑

切换创作模式时保留各自尚未提交的提示词、图片和参数草稿，直到应用退出。文字生图与图片编辑使用同一份当前连接配置。

## 8. 核心用户流程

### 8.1 单图整体编辑

1. 用户进入“开始”，选择“图片编辑”。
2. 点击上传区选择图片，或拖入、粘贴一张图片。
3. 保持“整体编辑”，输入修改要求。
4. 配置输出尺寸、质量、数量、背景和格式。
5. 点击“开始编辑”。
6. 客户端向当前连接的 `/images/edits` 发送请求。
7. 结果区展示生成图片；用户可以双击放大、下载、复制或继续编辑。

### 8.2 多参考图生成

1. 用户添加两张或更多图片。
2. 第一张显示“主图”标识，其余显示“参考 2”“参考 3”等标识。
3. 用户通过拖拽调整图片顺序，并在提示词中说明各图用途。
4. 客户端按界面顺序构造多个 `image[]` 字段并发送。
5. 结果写入画廊，历史详情保留输入图顺序。

### 8.3 Mask 局部编辑

1. 用户先添加主图，再选择“局部编辑”。
2. 用户点击“编辑区域”进入 Mask 编辑器。
3. 在图片上涂抹希望修改的区域，可调整画笔大小、撤销、重做和清空。
4. 用户确认 Mask，返回编辑页并输入修改要求。
5. 客户端自动生成与主图同尺寸、同格式且带 Alpha 通道的临时编辑图与 Mask。
6. 请求完成后，结果区提供“原图 / 结果”切换对比。

### 8.4 从结果继续编辑

1. 用户在当前结果或画廊卡片的更多菜单中选择“继续编辑”。
2. 客户端切换到“图片编辑”，将所选结果放入主图位置。
3. 默认清空旧 Mask；提示词保留并全选，便于立即改写。
4. 输出参数沿用原记录；用户确认后再次提交。

## 9. 详细功能需求

### 9.1 创作模式切换

- 默认进入上次使用的创作模式；首次安装默认“文字生图”。
- 文字生图按钮文案保持“开始生成”；图片编辑按钮文案改为“开始编辑”。
- 页面底部的参数摘要在图片编辑模式下增加输入数量与范围，例如：`3 张输入 · 整体编辑 · 2048 × 2048 · 高质量`。
- 未添加图片时，“开始编辑”按钮不可用，并提示“请至少添加一张图片”。
- 切换连接配置不清空编辑草稿，但提交时必须重新使用新连接的模型和能力校验。

### 9.2 图片导入

支持以下入口：

- 点击上传区打开系统文件选择器；
- 从 Finder/文件资源管理器拖入；
- 使用 `Cmd/Ctrl + V` 粘贴剪贴板中的图片；
- 从当前生成结果或画廊选择“继续编辑”。

客户端侧约束：

- 支持 PNG、JPEG/JPG、WebP；
- 单个文件最大 50 MB；
- 最多 16 张；
- 必须能够被 Electron 正确解码；
- 同一路径可以重复添加，但界面提示“已存在相同文件”，由用户决定是否保留；
- HEIC、GIF、SVG、TIFF、BMP 等格式不在本版请求范围内，提示用户先转为 PNG、JPEG 或 WebP；
- GIF 即使可预览，也不作为动画上传。

导入完成后，每张素材卡显示：

- 缩略图；
- 主图/参考图序号；
- 文件名；
- 像素尺寸；
- 文件大小；
- 替换和移除按钮。

排序规则：

- 支持拖拽排序；
- 第一张始终为主图；
- 局部编辑时，调整第一张图片会使已有 Mask 失效；执行前弹窗确认；
- 达到 16 张后隐藏“继续添加”入口并显示上限说明；
- 多图会增加输入成本和等待时间，在第 5 张起显示非阻断提示。

### 9.3 整体编辑

- 整体编辑不发送 `mask`。
- 单图可用于改风格、换背景、增删元素、修复画面或扩展构图。
- 多图可用于组合物体、参考人物或迁移风格。
- 提示词输入框上方提供三类快捷模板，仅填入可编辑文本，不自动提交：
  - “保留主体，修改……”
  - “参考第 2 张图的风格，将主图……”
  - “组合这些参考图中的元素，生成……”
- 模板中不承诺人物、文字或布局能够百分之百保持一致。

### 9.4 Mask 局部编辑器

#### 9.4.1 打开条件

- 必须已添加主图；
- 打开时使用主图原始像素尺寸建立编辑画布；
- 多参考图存在时仍只编辑主图，编辑器顶部明确提示“编辑区域仅应用于第 1 张主图”。

#### 9.4.2 编辑工具

P0 工具：

- 画笔：涂抹希望修改的区域；
- 橡皮擦：从编辑区域中擦除；
- 画笔大小：10–300 px，默认 80 px；
- 撤销、重做：至少保留最近 50 步；
- 清空：二次确认后清空全部编辑区域；
- 适合窗口、100% 显示；
- 鼠标滚轮缩放，按住空格拖动画布；
- 预览开关：显示/隐藏橙色半透明编辑覆盖层。

P2 工具：

- 反选编辑区域；
- `[`、`]` 调整画笔大小；
- `Cmd/Ctrl + Z` 撤销，`Cmd/Ctrl + Shift + Z` 重做。

#### 9.4.3 保存与转换

- 用户界面只表达“希望修改的区域”，不向用户暴露 Alpha 黑白规则；
- 提交前将主图和 Mask 统一转换为同尺寸 PNG；
- Mask 必须输出 RGBA PNG 并包含 Alpha 通道；
- 转换只生成请求用临时文件，不覆盖用户原图；
- 临时文件请求结束后删除；需要写入历史的副本单独保存；
- 没有涂抹任何区域时禁止确认，并提示“请先标记希望修改的区域”；
- Mask 是模型的引导而非精确像素裁切，编辑器底部常驻提示“模型可能对标记区域边缘做适当调整”。

### 9.5 提示词

- 编辑提示词必填，长度 1–32,000 个字符；
- 显示字符计数；
- 图片编辑使用独立的“恢复上次”内容，不覆盖文字生图的上次提示词；
- 多图时，提示词区域显示轻提示：“可用‘第 1 张主图、第 2 张参考图’说明各图片用途”；
- 从历史“复用提示词”进入时，仅复用文本；“按原参数继续编辑”才同时恢复输入图和参数。

### 9.6 输出参数

图片编辑复用 v0.4.0 已有参数控件：

| 参数 | 默认值 | 编辑模式规则 |
| --- | --- | --- |
| 尺寸 `size` | `auto` | 保持尺寸与质量独立；仍可使用按比例、自定义宽高和现有 GPT Image 2 尺寸校验。 |
| 质量 `quality` | `auto` | 取值 `auto/low/medium/high`；不与 1K/2K/4K 绑定。 |
| 数量 `n` | `1` | 取值 1–10。 |
| 背景 `background` | `auto` | 取值 `auto/opaque/transparent`。 |
| 输出格式 `output_format` | `png` | 取值 `png/jpeg/webp`。 |
| 压缩率 `output_compression` | `90` | 仅 JPEG、WebP 显示并发送。 |
| 审核 `moderation` | `auto` | 取值 `auto/low`，放在高级设置。 |
| 流式请求 `stream` | 跟随连接 | 使用当前连接的流式开关。 |
| 部分图 `partial_images` | `2` | 仅流式开启时发送，取值 0–3。 |

额外规则：

- `background=transparent` 时只允许 PNG 或 WebP；
- `gpt-image-2` 不显示、不发送 `input_fidelity`；
- OpenAI 官方连接沿用 v0.4.0 的灵活尺寸规则；
- 兼容服务若拒绝非标准尺寸，原样展示响应错误，不静默改写用户选择；
- 局部编辑默认 `size=auto`，不承诺输出尺寸与主图完全一致；用户可显式选择主图尺寸，但仍需满足 GPT Image 2 的尺寸规则。

### 9.7 请求发送

#### 9.7.1 端点

- 文字生图：`POST {baseUrl}/images/generations`；
- 图片编辑：`POST {baseUrl}/images/edits`；
- `baseUrl` 继续使用现有规范化逻辑；若用户误填完整编辑端点，保存时去掉 `/images/edits` 后缀；
- 请求超时和取消行为与文字生图一致。

#### 9.7.2 请求格式

编辑请求使用 `multipart/form-data`，由运行时自动生成 boundary，不手动设置 `Content-Type`。每张输入图按当前界面顺序添加为 `image[]`；局部编辑额外添加一个 `mask`。

示意请求：

```bash
curl -X POST "${BASE_URL}/images/edits" \
  -H "Authorization: Bearer ${OPENAI_API_KEY}" \
  -F "model=gpt-image-2" \
  -F "image[]=@main.png" \
  -F "image[]=@reference.png" \
  -F "prompt=保留主图构图，参考第 2 张图的材质重绘产品包装" \
  -F "size=2048x2048" \
  -F "quality=high" \
  -F "n=1" \
  -F "output_format=png"
```

#### 9.7.3 参数映射

| API 字段 | 是否发送 | 来源与规则 |
| --- | --- | --- |
| `image[]` | 必填 | 1–16 张，按界面顺序重复添加。 |
| `mask` | 局部编辑必填 | 一张 RGBA 图片，只作用于第一个 `image[]`。 |
| `prompt` | 必填 | 编辑提示词，1–32,000 字符。 |
| `model` | 必填 | 当前连接的模型名称。 |
| `size` | 必填 | 当前尺寸选择。 |
| `quality` | 必填 | `auto/low/medium/high`。 |
| `n` | 必填 | 1–10。 |
| `background` | 必填 | `auto/opaque/transparent`。 |
| `output_format` | 必填 | `png/jpeg/webp`。 |
| `output_compression` | 条件发送 | 仅 JPEG 或 WebP。 |
| `moderation` | 必填 | `auto/low`。 |
| `stream` | 必填 | 跟随当前连接，默认关闭。 |
| `partial_images` | 条件发送 | 仅 `stream=true`。 |
| `input_fidelity` | 不发送 | GPT Image 2 自动使用高保真输入且不允许修改。 |
| `user` | 不发送 | v0.5.0 不收集用户标识。 |

### 9.8 生成状态与结果区

- 上传图片后，右侧结果区未提交状态显示主图预览与“等待编辑”；
- 请求中显示已上传输入数量、耗时、取消按钮和流式部分图；
- 取消请求后保留输入图、Mask、提示词和参数，便于修改后重试；
- 成功结果沿用现有单张/多张展示、下载、批量下载、复制原图和文件位置功能；
- 双击结果打开大图查看器；
- 大图查看器增加“原图 / 结果”切换，局部编辑时增加“显示编辑区域”开关；
- 结果操作新增“继续编辑”，把所选结果设为新主图；
- 编辑永远生成新文件，不修改或覆盖输入图片。

### 9.9 画廊与历史记录

画廊卡片新增任务类型标识：

- 文字生图
- 整体编辑
- 局部编辑

编辑记录卡片：

- 主图仍显示第一张输出图；
- 参数徽标增加“1 张输入”或“4 张输入”；
- 局部编辑增加“局部编辑”徽标；
- 更多菜单增加“继续编辑”；
- “按原参数再生成”在编辑记录中改名为“按原参数再次编辑”。

编辑历史详情保存：

- 操作类型；
- 提示词；
- 输入图的顺序、角色、缩略图和本地副本；
- Mask 的缩略预览和本地副本；
- 输出参数、连接名称、模型、耗时、Request ID；
- 输出图片信息。

历史文件策略：

- 导入阶段只保留原文件引用和预览；提交时将输入图复制到任务临时目录；
- 请求成功后，把任务临时目录中的输入图和 Mask 转为正式历史副本，确保原文件移动或删除后仍可继续编辑；
- 请求失败或取消时清理任务临时副本，不生成孤立历史媒体；
- 仅保存应用管理的副本，不覆盖用户原文件；
- 单条编辑历史执行“删除”时，将该记录的输入副本、Mask 副本和输出图一并移到系统废纸篓；
- “清空记录”沿用现有语义：只清空索引并保留媒体文件，确认弹窗需明确可能继续占用磁盘空间；
- 历史仍最多保留 200 条索引记录；超出上限时只移除最旧索引，不自动删除媒体文件。

### 9.10 连接设置与兼容服务

连接配置卡片新增只读能力状态：

- 图片生成：未知 / 已支持 / 不支持；
- 图片编辑：未知 / 已支持 / 不支持。

能力状态规则：

- 新建或迁移的配置初始为“未知”；
- 普通“测试连接”仍只验证鉴权、Base URL 和模型可见性，不发送付费图片请求；
- 第一次编辑请求成功后标记“已支持”；
- `/images/edits` 返回明确的 `404`、`405` 或兼容服务提供的“不支持端点/模型”错误后标记“不支持”；
- 鉴权、限流、余额不足、审核、超时或服务器临时错误不得标记“不支持”；
- “不支持”仅作为提示，用户仍可强制再次尝试。

当编辑端点不支持时，错误提示为：

> 当前服务未提供 OpenAI 兼容的图片编辑接口 `/images/edits`。文字生图仍可使用；请联系服务提供方确认 GPT Image 2 编辑能力。

### 9.11 请求日志

请求日志抽屉继续从设置页右上角打开。图片编辑日志类型显示“图片编辑”，并记录：

- 连接名称、模型、端点、HTTP 方法；
- 图片输入数量；
- 每张图片的序号、角色、文件类型、宽高和字节数；
- 是否包含 Mask，以及 Mask 的宽高和字节数；
- 提示词及所有非敏感输出参数；
- 状态、耗时、HTTP 状态、Request ID；
- 成功时的输出数量与 usage；
- 失败时的错误代码和响应体。

日志禁止记录：

- API Key 或 Authorization 请求头；
- 图片二进制、Base64、Data URL；
- 用户文件的完整本地路径；
- 应用内部加密密钥。

文件名在日志中仅保留经过清理的基本名称；若存在隐私风险，可只显示 `image-1.png` 这类序号名称。

### 9.12 错误处理

| 场景 | 用户提示 | 是否保留草稿 |
| --- | --- | --- |
| 未添加图片 | 请至少添加一张图片 | 是 |
| 超过 16 张 | 每次最多添加 16 张图片 | 是 |
| 单图超过 50 MB | 图片超过 50 MB，请压缩后重试 | 是 |
| 不支持的格式 | 仅支持 PNG、JPEG 和 WebP | 是 |
| 图片无法解码 | 无法读取此图片，文件可能已损坏 | 是 |
| 未绘制 Mask | 请先标记希望修改的区域 | 是 |
| Mask 转换失败 | 编辑区域处理失败，请重新绘制 | 是 |
| 编辑端点不存在 | 当前服务可能不支持 `/images/edits` | 是 |
| 401/403 | API Key 无效或没有该模型权限 | 是 |
| 429 | 请求过多或额度不足，请稍后重试 | 是 |
| 超时 | 请求已超时，可提高超时时间后重试 | 是 |
| 用户取消 | 已取消编辑 | 是 |
| `moderation_blocked` | 请求未通过安全检查，请调整提示词或输入图片 | 是 |
| `image_generation_user_error` | 根据响应代码给出可修改提示，不自动重试 | 是 |
| 5xx | 服务暂时不可用，请稍后重试 | 是 |

自动重试规则：

- v0.5.0 不自动重试图片编辑，避免重复计费；
- 429 和 5xx 可在错误卡片提供“重试”按钮；
- 用户错误、审核错误、401/403、404/405 不提供自动倒计时重试。

## 10. 数据结构与迁移

### 10.1 历史记录结构

当前 `history.json` 是未版本化的数组。建议升级为 `{ "version": 3, "entries": [] }` 包装结构，读取器同时兼容旧数组。单条 v3 记录新增字段示意：

```json
{
  "id": "task-id",
  "operation": "edit",
  "editMode": "mask",
  "prompt": "把桌上的杯子改成透明玻璃杯",
  "inputs": [
    {
      "id": "input-1",
      "role": "base",
      "storedPath": "...",
      "thumbnailPath": "...",
      "mimeType": "image/png",
      "width": 2048,
      "height": 2048,
      "bytes": 1234567
    }
  ],
  "mask": {
    "storedPath": "...",
    "thumbnailPath": "...",
    "width": 2048,
    "height": 2048,
    "bytes": 24567
  },
  "parameters": {
    "size": "2048x2048",
    "quality": "high",
    "n": 1,
    "background": "auto",
    "outputFormat": "png",
    "moderation": "auto",
    "stream": false
  },
  "images": [],
  "createdAt": "2026-08-27T00:00:00.000Z"
}
```

字段约束：

- `operation`：`generate | edit`；
- `editMode`：文字生图时为空，编辑时为 `full | mask`；
- `inputs[0].role` 固定为 `base`，其余为 `reference`；
- 路径只在本机历史文件中保存，不写入请求日志或导出的图片参数；
- 数据加载时对路径进行允许目录校验，防止任意文件访问。

### 10.2 迁移规则

- v0.4.x 历史记录自动补充 `operation: "generate"`；
- 未版本化的旧历史数组迁移为 `{ "version": 3, "entries": [...] }`；
- 旧记录的 `editMode`、`inputs` 和 `mask` 为空；
- 现有 `config.json`、加密密钥、连接配置和请求日志不重置；
- 新增连接能力字段时默认 `unknown`；
- 迁移写入采用临时文件加原子替换；失败时保留旧文件并提示，不得生成半迁移状态。

## 11. 技术与安全要求

### 11.1 进程边界

- Renderer 只持有用于预览的受控 URL 和素材元数据；
- 文件读取、格式探测、临时文件创建、请求发送和历史副本管理在 Electron 主进程完成；
- Preload 只暴露最小化 IPC：选择图片、读取安全预览、提交编辑、取消、保存 Mask、继续编辑；
- IPC 参数必须校验任务 ID、连接 ID、文件数量、文件大小、格式和允许路径；
- 不向 Renderer 暴露 API Key。

### 11.2 性能

- 不通过 JSON/IPC 传输完整图片 Base64；
- 缩略图最长边建议 640 px，并缓存到应用数据目录；
- 大图预览按需加载，关闭查看器后释放对象 URL；
- Mask 编辑器显示分辨率可降采样，但导出 Mask 必须映射回主图原始像素尺寸；
- 单次只允许一个图片生成或编辑请求，避免意外并发计费；
- 16 张大图导入时必须保持界面可响应，并显示素材处理进度。

### 11.3 隐私与文件安全

- 输入图仅发送给当前选中的 API 服务；
- 提交前在确认区域显示实际目标域名；
- 非本机地址继续强制 HTTPS；
- 本地副本和历史文件权限沿用现有用户私有设置；
- 不增加遥测、崩溃上报或云端同步；
- API Key 的保存策略保持 v0.4.0 不变。

## 12. UI 状态要求

图片编辑页至少覆盖以下状态：

1. 空状态：未选择图片；
2. 素材处理中：正在读取尺寸和生成缩略图；
3. 可编辑：图片与参数有效；
4. 参数错误：对应控件就地提示；
5. 请求上传中：显示输入图数量和进度型提示，不虚构精确百分比；
6. 模型处理中：显示耗时和取消；
7. 流式预览：以“预览中”标识区别最终图；
8. 成功：展示最终图片与操作；
9. 失败：展示错误摘要、Request ID、重试和查看日志；
10. 已取消：保留草稿并允许重新提交。

Mask 编辑器至少覆盖：未绘制、已绘制、撤销后为空、导出中、导出失败五种状态。

## 13. 验收标准

### 13.1 图片输入

- [ ] 可通过文件选择器、拖拽和剪贴板添加 PNG、JPEG、WebP。
- [ ] 添加第 17 张图片时被客户端阻止。
- [ ] 超过 50 MB、损坏或不支持格式的文件不会进入请求列表。
- [ ] 可拖拽改变顺序，第一张主图标识随顺序更新。
- [ ] 移除或替换主图时，已有 Mask 被清除或经确认后清除。

### 13.2 整体与局部编辑

- [ ] 单张输入能成功调用 `/images/edits` 并得到结果。
- [ ] 多张输入按界面顺序形成多个 `image[]`。
- [ ] 整体编辑请求不包含 `mask`。
- [ ] 局部编辑请求包含一个 Mask，且只作用于第一张输入图。
- [ ] 发送前主图与 Mask 的尺寸、格式一致，均包含可读取的图像数据。
- [ ] 未绘制区域时无法提交局部编辑。
- [ ] `gpt-image-2` 请求中不出现 `input_fidelity`。

### 13.3 参数与响应

- [ ] 尺寸和质量独立配置，切换质量不会改变尺寸。
- [ ] `output_compression` 仅在 JPEG/WebP 时发送。
- [ ] 透明背景与 JPEG 的冲突在客户端拦截。
- [ ] 普通 Base64 响应和兼容服务 URL 响应均可保存。
- [ ] 开启流式时能展示部分图；关闭时不发送 `partial_images`。
- [ ] 取消和超时不会产生成功历史记录，但会保留可重试草稿与日志。

### 13.4 历史、日志与隐私

- [ ] 编辑记录在画廊中有明确类型和输入数量标识。
- [ ] “继续编辑”能恢复结果为主图；“按原参数再次编辑”能恢复素材、提示词与参数。
- [ ] 原始用户文件被移动或删除后，历史副本仍可用于继续编辑。
- [ ] 删除单条编辑历史会把其应用管理的媒体文件移到系统废纸篓。
- [ ] 请求日志能显示编辑参数、素材元数据和失败响应体。
- [ ] 请求日志中不存在 API Key、Authorization、图片 Base64 或完整本地路径。
- [ ] v0.4.x 样例库、历史、连接和密钥升级后仍可正常使用。

### 13.5 兼容性

- [ ] OpenAI 官方 `gpt-image-2` 可完成单图、多图和 Mask 编辑。
- [ ] 兼容服务返回 404/405 时展示端点不支持提示，不影响文字生图。
- [ ] 429、5xx、超时和鉴权错误不会错误地把连接标记为“不支持编辑”。
- [ ] Windows x64、macOS arm64、macOS x64 安装包通过基本流程测试。
